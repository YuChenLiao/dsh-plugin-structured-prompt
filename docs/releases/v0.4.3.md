# v0.4.3

## 修复

**「对话刚开始」时自动填充取不到模型。**

`0.4.2` 解决了"读不到会话模型"的服务可见性问题，但漏了一种更常见的情况：**新会话还没有模型选择**。用户没切换过模型、也还没发过请求，所以 `modelSelection` 投影的 `lastUsed` 与 `pending` 都是 `null`。

DSH 自己的回退链是 `pending → 会话 requestHeader → agentDefaultModel`（`session-controller/src/agent.ts:283-291`）。我们只对齐了前两级，于是一开新对话必然落空。现在补上最后一级：会话里读不到时回退到宿主的**默认模型**（`agentDefaultModel.currentSelection()`）。

完整优先级：会话正在用的模型 → 宿主默认模型 → 装载行 `assistProvider` / `assistModel`。

## 错误消息

三级都落空时，消息会同时给出两级读取各自的卡点，例如：

```
读不到可用的模型（会话模型：这个会话还没有模型选择（先在本会话里发一条消息，让它跑过一轮请求）；
默认模型：拿不到 agentDefaultModel 服务）；也没有配置 assistProvider / assistModel
```

## 升级

装完**重启 DSH**。
