# v0.4.1

## 修复

**安装自检把正常的 npm 安装判成失败。** `tests/verify-install.mjs` 里那条"依赖指向本插件"只认 `link:` 与 `github:` 两种规格，所以从 npm 装上来的 `0.4.0` 会被判红。现在三种都接受，并额外核对安装形态（`link:` 应当指向源码、registry 安装应当是独立副本）。

**补上 npm 发布形态的守护。** 新增五项检查：`private` 必须不存在、`files` 必须含 `lib` / `cordis.patch.yml` / `README.md`、`files` 不得含 `src` / `tests` / `tools`、`publishConfig` 固定到 npmjs、`exports` 三个入口与 `dsh` 字段（`bundle.patch` 与 `client.platform`）都在。最后一项尤其重要：缺了 `dsh` 字段，包装上了但界面不会加载。

## 文档

README 新增「从 npm 安装」与「切换安装方式之前，先清掉旧条目」两节，写清了 Windows 上从 `link:` 换装的 `EPERM ... rename '..._tmp_...'` 及其处理顺序（关 DSH → 删旧条目 → 重新 add），以及"`dsh plugin add` 在已安装时可能不补写 `dsh.profile.bundles`"这个坑。

## 关于那个 EPERM

它不是包内容的缺陷。`0.4.0` 的包在隔离目录里实测可正常安装（含持有产物文件句柄的情形），装成的包包含 `docs` / `lib` / `cordis.patch.yml` / `LICENSE` / `package.json` / `README.md` 六项、版本正确。失败发生在 pnpm 替换旧 junction 的那一步，属于安装现场状态问题。

## 升级

```powershell
dsh plugin --profile desktop add dsh-plugin-structured-prompt
```

装完**重启 DSH**。
