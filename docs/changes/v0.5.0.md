# v0.5.0 —— 表单从弹窗搬到侧栏（2026-11）

## 起点：一个修不干净的定位

弹窗位置在真机上被修过三轮（基准不是视口 → 取第一个够宽的祖先 → 补偿 `fixed` 的包含块原点），
每次都更接近，但都没结束。第三次之后的结论是：**这套测量本身不该存在**。基准是"弹窗所在的列"，
而"列"是宿主布局的实现细节；插件越猜，越依赖副作用（`transform` 改掉包含块、宽度为 0 的槽位父元素）。

所以本批做的是换外壳，不是再修坐标：表单本体拆出来，挂在宿主的侧栏里，位置与尺寸由宿主给。

## 做了什么

1. **拆出表单本体**（`ui/FormPanel.tsx`）：标题栏 + 内容区 + 底栏，不含遮罩、不含尺寸。
   弹窗（`ui/Modal.tsx`）退回到"只做遮罩 + 尺寸 + 按列定位"。
2. **接入链**（`client/sidebar.ts`）：`dsh-better-sidebar` → 宿主原生右侧栏 → 弹窗。
   两个后端各自一个文件，探测判据共用 `client/probe.ts`，降级文案在 `client/sidebar-note.ts`。
3. **非插槽的 tab 主体**（`ui/BetterTab.tsx`）：better-sidebar 的 tab 不是插槽组件，拿不到
   `useStore` 座位，只能自己 `store.create(sessionId)` —— 因此 `createStructuredInputStore`
   按 `scopeKey` 缓存实例，四处界面才是同一份状态。

## 踩到并写进代码的三件事

**其一，接入必须顺序无关。** 第一版在 `apply()` 里用 `ctx.get('sidebarRightTabs')` 探测一次就定生死，
真机结果"出来的还是弹窗"：探不到就静默降级，入口连 `open` 都没拿到。现在三条路都走 ——
apply 期探测 / `ctx.inject` 等它出现 / 打开时再探。后到的 better-sidebar 会顶掉已挂上的原生类型。

**其二，`openTab` 会静默拒绝。** better-sidebar 的类型被设置页关掉、描述符不在注册表、没有目标会话时，
`openTab` **只 return、不抛错**。不先自证，`open()` 就返回 `true`，入口不退回弹窗 —— 用户按下没反应。
现在打开前先问 `isTabEnabled` / `getTab` / `getSnapshot().sessionId`，任一不成立就收敛成 `false` + 原因。

**其三，状态可能分裂。** `defineStore.create()` 刻意不去重（"instance uniqueness per key is the
caller's responsibility"），而 better-sidebar 的 tab 主体不是插槽、只能自己 `create`。不缓存实例的话，
侧栏里改了表单、弹窗里看不到，「库 → 表单」的补丁也会落进没人显示的那一份。

## 契约与不变量

- 黄金样本 25 条逐字未变（本批不碰构建器）。
- `inject` 仍只有 `slots`：侧栏服务**不进**导出声明 —— 老宿主没有它们，写进去会让整个插件停在 PENDING。
- host 产物零运行时 import；单文件 ≤ 260 行（`sidebar.ts` 顶到上限后把文案拆成了 `sidebar-note.ts`）。
- 两个组件仍互不 import。

## 两轮审查（都已修，不再复述过程）

第一轮查契约与正确性，抓出「静默拒绝」与「服务实例被替换后接入停在旧实例」两条死键；
第二轮专职挑战断言，抓出三条"改坏了仍然全绿"的新断言（活订阅在 SSR 里测不到、`open()` 非可选调用会
把后面的断言全吞掉、负向正则被一行注释打红），以及扩写三条守卫零覆盖。

修完后 12 条注入式突变各自打红，八套全绿。

## 决定不做

- 提示词库的检索弹窗**不迁**：先验证这条通路稳定，再决定要不要一起搬。
- store 实例缓存**不做淘汰**：淘汰会让还挂着的界面悄悄改用另一份实例（状态分裂比内存泄漏严重）；
  没有 `persist` 时一个会话一条的代价可忽略。加 `persist` 之前必须补按作用域释放。
- 三条 SSR 覆盖不到的路径（Esc 关闭、`useFormPatch` 整段、`eq` 记忆槽）留作后续：
  需要把它们各自抽成纯函数才可断言，属于另一批的量。
