# 自动扩写填表（2026-10，分支 feat/assist-autofill）

## 做什么

表单里写一句需求 → 宿主跑一次**子代理**把它扩写成结构化字段的增量补丁 → 补丁填进表单。

链路：浏览器 → 同源路由 POST /api/structured-prompt/assist → subagents.start → 浏览器。
**主 agent 上下文里看不到任何内容**（对比工具路径 host/tool.ts 的 delegate：那条是把结果
返回给模型）。唯一痕迹是会话树里会多一个子会话 —— 别写成"完全无痕"。

## 三条硬约束

1. **父级必须是一个 Session**（DSH subagent/src/catalog.ts 是 parent: Session），所以请求带
   sessionId；indSession 按鸭子类型探测（能 ppend 才算 Session），取不到报 409 ——
   不编假父级。这条判据是审查加的：原先"任意非空返回值就当 Session"，拿到快照/scope 时会抛
   parent.append is not a function，而那条错误会原样回给用户。
2. **模型输出必须过校验**：xtractJsonObject（括号配对扫描，取第一个完整对象，不修补）+
   parseFormDocument（复用导入那条路径）。全部字段被丢弃 → 502，不落空表单。
3. **素材不可伪造边界**：{request, existingFields} 整体 JSON 包裹进提示词。文本拼接时素材里写
   --- 素材结束 --- 就能逃出隔离区（审查实测的 M1）。

## 审查抓到的那条阻断

setForm(patch) 走 completeForm，会把模型**没返回**的字段填成空值 —— 用户填了 5 个字段、点
一下自动填充、模型只给 2 个，剩下 3 个被清空。而代码注释里写着"避免覆盖用户内容"，与实现相反。
改成新增 mergeForm（只覆盖给定的键），顺带避开"异步回调里用旧快照"的竞态。

这条的教训：**"补丁"这个语义在 store 上没有对应动作时，借用了"整表替换"**。断言当时一条都没覆盖
主链，所以八套全绿也发现不了。

## 断言与反向验证

- 主链（模型返回 JSON → 提取 → 校验 → patch/warnings）、全部被丢弃 → 502、父级不像 Session → 409、
  素材 JSON 包裹、入参白名单、渲染侧的四种状态（含 data-assist-status 锚点）。
- 反向验证：把校验换成"直接采用" → 2 条红；把 Session 判据改恒真 → 3 条红。

## 修订：单次调用优先（使用者指出偏离）

第一版实现走了子代理路径，而方案里推荐的是 `llm.stream` 单次调用。当时放弃它的理由只是"参数形状
没核实、不想猜"——但这该让我先核实，而不是换一条更重的路。

核实后（`packages/llm/llm/src`）：服务名 `llm`（`index.ts:342` 的 `super(ctx, 'llm')`），
`stream(options)` 返回 `AsyncIterable<StreamChunk>`，其中 `text-delta` 就是产物。**但
`GenerateOptions.provider` 与 `.model` 都必填、且没有默认值来源** —— 这才是单次调用必须配模型的
真实原因，也是当初没讲清的代价。

于是改成：配了 `assistProvider` + `assistModel` → 单次调用；否则或单次调用失败 → 子代理；都没有 → 501。

单次调用的好处不只是"轻"：**没有工具、没有 agent loop**，输出就是那段 JSON；而子代理是完整 agent，
可能先调工具或思考再输出，JSON 的确定性低得多。且单次调用不在会话树留子会话。

**未验证**：`Message` 的 `id` / `source` 照最小形状构造（host 产物零 import，拿不到 DSH 的工厂与
类型）。某个 adapter 若有额外要求，路径 1 会抛错 —— 所以它的失败**自动回退**到路径 2，猜错不会
变成功能不可用。

一处值得记的断言教训：这条路径的"只认 `text-delta`"最初写着 `reasoning-delta` 的文本是纯中文，
突变实验**没红** —— 因为提取器会跳过前缀、照样取到后面的 JSON。把思考文本改成含花括号的完整 JSON
之后，一旦它被误收，提取器就会取到那个对象，断言才真正有证伪力。

## 已知边界

- **真实子代理没跑过**（离线测不了）：模型是否老实只输出 JSON、是否漏字段，只能上线看。阻断的
  严重性正取决于"漏字段"的常见程度 —— 修完 mergeForm 后漏字段只会"补不全"，不再"清空"。
- 没有取消按钮：95 秒硬等，关弹窗后请求仍在跑、结果仍会写进表单（有了 mergeForm 不再丢数据，
  但用户不在场时字段会被改动）。
- sessions 服务的真实形状仍未在源码里定位到（packages/session* 全是子包），所以父级探测只能
- `sessions` 服务的真实形状仍未在源码里定位到（`packages/session*` 全是子包），所以父级探测只能
  靠鸭子类型；`get` / `byId` / `find` / `resolve` 哪个是"按 id 取"，待运行环境确认。

## 审查记录（合并进主干前）

| 轮次 | 结论 | 关键项 |
| --- | --- | --- |
| 第一轮（单功能） | 1 阻断 + 5 需修 | 阻断是**数据丢失**：`setForm(patch)` 走 `completeForm`，把模型没返回的字段清空 —— 而注释写着"避免覆盖用户内容"。改为 `mergeForm` |
| 第二轮（整批，合并前） | 无阻断，5 需修 | 核心一条：**上一轮那条阻断没有回归测试**（把 `mergeForm` 改回 `completeForm`，八套零红）。另四条是 413 无守护、括号配对无守护、`llm` 缺失时消息误导、README 把子代理写成可用 |
| 复核 | 4 条已修，第 5 条未到位 | README 正文三处仍把 `delegate` 当可用能力演示，与文件清单里的"当前版本不可用"自相矛盾 —— 改完才打标 |

三条新断言的突变复验（复核查自行重跑，全部变红）：`mergeForm`→`completeForm`、去掉长度上限、括号扫描换成
`indexOf`/`lastIndexOf` 切片。

两处过程教训值得记：

- **突变零红时先怀疑突变本身**。我第一次验"括号配对"时在捷径后面加了失败回退，行为不变，自然零红 ——
  那不是守护缺口，是我把突变写成了等价改写。换成"失败即 undefined"才红。
- **校验命令里的反引号**。用 PowerShell 双引号字符串写校验正则时，反引号是转义符，会被吃掉导致
  匹配失败；我据此误判"未插入"又插了一遍，README 里出现重复行。改用单引号或按行号操作。
