## 使用者可感知的行为变更

1. **全空白数组算「未给」**（`f9c238b`）：`rules: ['']`、`callable_tools: ['']` 现在与空数组等价 ——
   回退模板底座，而不是清空它。此前同一个输入在两个字段上行为相反：`rules` 走 `prefer`（只看数组
   长度）会清空底座，`callable_tools` 按内容判定会回退底座。
2. **provider 默认值可从装载行配置**（`39ac74b`）：`cordis.patch.yml` 的装载行支持
   `config: { provider: 'fork' }`，优先级为「调用参数 `delegate.provider` > 装载行 `config` >
   内建默认 `spawn`」。不写 `config` 时行为与 v0.2.0 逐字相同。
3. **配置形状不合法在装载期报错**：`config` 不是对象、含不支持的字段、或 `provider` 不是字符串
   时，cordis 抛 `ValidationError` 且 `apply` 不被调用。两点边界：`provider` 名**是否已注册**要到
   第一次 `delegate` 才校验；`provider` 必须写在 `config:` 之下（写成条目层会被 loader 原样保留，
   既不报错也不生效 —— 这条属 loader 行为，需真机确认）。
4. **工具对模型的说明文案**：`delegate.provider` 的 description 由「the default (a one-shot run)」
   改为「the deployment default」—— 默认值现在可以被部署改，旧文案会让模型误判语义。
5. **以冒号开头的工具条目**（`: 用途`）不再被当成名叫 `: 用途` 的工具，而是与空工具名行一样整行
   忽略。

## 契约与不变量

- **黄金样本 16 → 20 条**，原有 16 条**逐字未变**（`.gitattributes` 的 `tests/golden/*.txt` LF 约定
  继续生效）。
- **host 产物仍零 import**：静态 `import`、动态 `import(`、`require(` 三条都在断言里。`Config` 是
  **手写**的 standard-schema 对象（`{ '~standard': { version, vendor, validate } }`），不引入校验库
  —— cordis 的 `resolveConfig` 只消费 `['~standard'].validate`。
- **导出面**：`inject` / `Config` / `apply`，全部命名导出、没有 default（函数插件混用 default 会让
  Loader 丢掉整个命名空间）。
- **README 的硬事实**由「文档契约」套机器核对，且文件清单改为**双向**：`src/` 下每个文件都必须出现
  在 README 的文件清单里。该断言在落地当轮就抓出三处漏列（`host/config.ts`、`client/send.ts`、
  `client/plugin-context.ts`）。
- **工具名与用途整组同进同退**：由 `resolveCallableTools` 这个纯函数承载，可直接断言 —— 底座为空
  时"一退一留"在产物上不可观测，只能测函数本身。

## 评估后决定不做

| 方案 | 结论 | 依据 |
| --- | --- | --- |
| 「越界枚举的拒绝」做成黄金样本 | 不做 | 黄金套的取数路径直接调 `narrowArgs`，抛错会让整套以未捕获异常终止，而黄金机制只比对产出的文本。该断言留在 `test-tool.mjs` |
| `applyFormatChoice` 的「骨架 + 追加」进 host 黄金样本 | 不做 | 四套模板都不带 `outputSpec`，底座经 `completeForm` 补成空串，只能命中"整段填入"分支；`extends` 分支恒不成立。要构造它得给模板加带骨架的 `outputSpec`（产品改动），并漂移四条 `template-*` 样本 |
| 不导出 `Config`、校验全由插件自己做 | 改为导出 `Config` | 初版论据是"导出 schema 必须 import 宿主包"，审计指出 `import type` 在 emit 时被完全擦除、本地声明子集本就是本仓现成做法；导出后校验由 cordis 统一执行、错误类型统一 |
| 用 `defineTool` 构造工具定义 | 不做（沿用 v0.2.0 的结论） | `link:` 安装下 ESM realpath 到源码目录，那里没有 `node_modules`；import 宿主包会让插件在启动期失败 |

## 待决策 / 需真机

  仍在、`inject: ['tools']` 正常、以及（可选）临时写 `config: { provider: 'fork' }` 是否生效。
- README 里几条静态无法判定的表述（客户端能否对单次对话注入 system prompt、store 更新是否触发槽位
  重渲染、以及历史计数）留待真机或历史记录确认，本轮没有改写。
